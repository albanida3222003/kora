Los 3 Módulos del Proyecto

MÓDULO 1

🛒 Web Cliente

  • Catálogo de restaurantes y productos.
  • Carrito de compras multilocal.
  • Registro/Login de usuario.
  • Ubicación por GPS/mapa y cálculo de envío.
MÓDULO 2

📊 Dashboard Admin

  • Login exclusivo para el administrador.
  • Alta y edición de locales y productos.
  • Gestión de categorías y precios.
  • Vista general de pedidos y métricas.
MÓDULO 3

📱 App Móvil para Locales (Flutter)

Aplicación nativa desarrollada en Flutter, conectada al mismo backend de Supabase que la Web Cliente y el Dashboard, para que cada restaurante gestione sus propios pedidos:

  • Login por local: cada restaurante ingresa con su propia cuenta (mismo sistema de autenticación de toda la plataforma).
  • Notificación de pedidos: alerta en tiempo real ante un nuevo pedido (Supabase Realtime).
  • Aceptar / Rechazar: el local decide si toma el pedido.
  • Tiempo estimado: el local define cuánto tardará en preparar el pedido.

Arquitectura Técnica

Tecnologías Utilizadas

WEB CLIENTE + DASHBOARD ADMIN

HTML5 / CSS3 / JavaScript

  • Interfaz responsiva, optimizada para navegadores móviles y de escritorio.
  • GitHub Pages: hosting gratuito, con SSL incluido.
APP MÓVIL DE LOCALES

Flutter

  • App nativa (Android/iOS) desde un único código base.
  • Conectada al mismo backend mediante el SDK supabase_flutter.
BACKEND & BASE DE DATOS (compartido por los 3 módulos)

Supabase

  • Auth: un mismo sistema de login para cliente, admin y locales — funciona igual desde la web (JS) y desde la app (Flutter).
  • Base de datos y Realtime: pedidos sincronizados al instante entre la Web Cliente y la App de Locales.
  • Storage: imágenes de logos, banners y productos.
// Flujo general del sistema:
Cliente → crea pedido en Web Cliente (JS + Supabase);
Local → recibe notificación en App Móvil Flutter en tiempo real;
Admin → supervisa todo desde el Dashboard (JS + Supabase).
📌 Distribución de la app: se entrega como APK instalable directamente en los dispositivos de cada local, sin costo adicional.
Costos Fuera del Proyecto

Infraestructura, Dominio y Escalabilidad

El desarrollo cubre el sistema completo, pero hay dos puntos de infraestructura que dependen de servicios externos y que el cliente debe conocer desde ahora.

DOMINIO WEB

🌐 Nombre de dominio (opcional, no incluido)

GitHub Pages ya incluye una dirección gratuita (ej. usuario.github.io), 100% funcional para lanzar el proyecto. Si el cliente prefiere una dirección propia (ej. www.milocal.com), la compra del dominio corre por su cuenta, con un costo aproximado de $12 - $15 USD al año en proveedores como Namecheap o GoDaddy. Este costo es recurrente (anual) y externo al pago del desarrollo.

LÍMITES DE SUPABASE

📊 ¿Qué pasa si se rebasa el límite gratuito?

El plan gratuito de Supabase incluye hasta 500 MB de base de datos, 1 GB de almacenamiento de imágenes y 50,000 usuarios activos al mes — suficiente para el lanzamiento y los primeros meses de operación.

  • Si el proyecto crece y se supera alguno de estos límites, Supabase no borra ni bloquea la información, pero limita ciertas funciones hasta actualizar el plan.
  • La solución es pasar al Plan Pro de Supabase, con un costo aproximado de $25 USD al mes, que amplía considerablemente estos límites.
  • Este es un costo de mantenimiento a futuro, no del desarrollo actual, y solo aplicaría cuando el negocio ya esté generando volumen real de pedidos.
📌 En resumen: el proyecto puede lanzarse con S/ 0.00 de costo mensual. El dominio propio y el plan Pro de Supabase son mejoras opcionales que se activan solo si el cliente las necesita.
